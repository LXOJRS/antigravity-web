### Git branches

Demonstrated with a sandbox branch in this session (created, switched, committed, switched back to main, deleted). Alex now knows:

- `git checkout -b name` to create + switch
- `git checkout main` to return
- `git branch -d name` to delete (lowercase for safety; `-D` to force-delete unmerged)
- Branches are isolated timelines; switching swaps files on disk
- Pushing optional: `git push -u origin branch-name` to back up to GitHub

The intended use: create a branch per Lens AI direction (`lens-ai-direction-2`, `lens-ai-direction-1`, etc.), implement on the branch, deploy to a Firebase preview channel, compare URLs, merge winner to main.

### Firebase preview channels

Mentioned as the next chapter but **not set up**. The intended workflow: use `firebase hosting:channel:deploy <channel-name>` to deploy a branch to its own preview URL, so Alex can SEE different design directions before committing one to main. This was the point of the branching demo — branches give isolated code, preview channels give isolated URLs.

If Lens AI work resumes, setting up the first preview channel is logical step 1 before any branch-based design experiments.
